## 3. 核心任务执行

### 3.1 学习策略评估理论

### 3.2 编写策略评估脚本 `scripts/strategy_evaluation.py`
- 定义旧策略：`credit_score > 600` 则通过，否则拒绝。
- 定义新策略：`credit_score > 600` 或 `amount < 5000` 则通过，否则拒绝。
- 从 `feature_apply_broad_v3` 加载历史数据，计算两种策略下的通过率和通过样本坏账率。
- 使用卡方检验判断通过率和坏账率变化是否具有统计显著性。
- 生成策略评估报告 `reports/strategy_evaluation_report.md`。

### 3.4 结果分析

- 新策略通过率从 70.0% 提升到 78.0%（+8%），但坏账率从 5.0% 上升到 6.5%（+1.5%）。
- 卡方检验 p 值均 < 0.05，说明两个指标的变化均非偶然。
- 是否上线需结合业务收益模型：若新策略带来的利润增量超过坏账损失，则值得上线；否则需继续调优。

## 4. 遇到的问题与解决方案

| 问题                                     | 原因                    | 解决方案                                                   |
| :--------------------------------------- | :---------------------- | :--------------------------------------------------------- |
| 卡方检验要求列联表各单元格计数 ≥ 5       | 某些策略通过/拒绝数极少 | 使用 Fisher 精确检验（`scipy.stats.fisher_exact`）作为备选 |
| 新策略坏账率上升但可能因样本量不足而波动 | 测试集有限              | 增加历史数据量，或使用交叉验证                             |
| 策略函数硬编码，难以扩展                 | 缺乏配置化              | 将策略规则存储到 `config.yaml`，动态加载                   |

## 6. 思考题

- **离线回溯测试和在线 A/B 测试各有什么优缺点？**
  离线测试快速、无风险，但无法反映用户行为变化；在线测试结果真实，但成本高、周期长。
- **如果新策略的通过率上升，但坏账率也上升，如何决策？**
  计算综合收益（利润 = 通过率 × (单笔收益 × (1-坏账率) - 坏账损失)），若净收益为正则考虑上线。
- **如何确定 A/B 测试的样本量？**
  根据预期提升幅度、显著性水平（α=0.05）、功效（80%）计算，可使用 `statsmodels` 或在线计算器。
