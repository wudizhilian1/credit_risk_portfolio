## 3. 核心任务执行

### 3.1 学习滑动窗口概念
- **滑动窗口**：窗口长度 5 秒，滑动步长 1 秒，每 1 秒输出最近 5 秒内的事件总数。
- 与滚动窗口的区别：滚动窗口无重叠，滑动窗口有重叠，适用于连续监控场景。

### 3.2 实现事件生成器 `event_generator`
- 每秒随机生成 0-3 个事件。
- 每个事件包含 `event_id`, `event_type`, `user_id`, `timestamp`。
- 无限循环生成，模拟实时数据流。

### 3.3 实现滑动窗口计数器 `SlidingWindowCounter`
- 使用 `deque` 存储窗口内的事件时间戳。
- 支持全局计数和按 `user_id` 分组计数。
- 独立线程每隔 `slide_sec` 秒输出当前窗口内的事件数。
- 线程安全：使用 `threading.Lock` 保护共享数据。

## 4. 遇到的问题与解决方案

| 问题                              | 原因                               | 解决方案                                                     |
| --------------------------------- | ---------------------------------- | ------------------------------------------------------------ |
| 窗口内事件数总是为 0              | 事件时间戳为整数秒，清理逻辑错误   | 统一使用 `time.time()` 浮点时间戳，清理时用 `< current_time - window_sec` |
| 多线程修改 `deque` 导致数据不一致 | 未加锁                             | 在 `add_event`、`get_count` 中使用 `threading.Lock` 保护     |
| 分组统计时字典在迭代中修改        | `_sliding_loop` 遍历时可能新增 key | 打印快照时复制字典副本 `snapshot = {k: len(dq) for k, dq in self.events.items()}` |

## 6. 思考题
- **滑动窗口和滚动窗口的区别是什么？分别适用于什么场景？**  
  滚动窗口无重叠，适用于固定周期聚合（如每小时统计）；滑动窗口有重叠，适用于连续监控（如每 1 秒输出过去 5 秒的平均值）。
- **如果事件时间严重滞后（迟到数据），如何保证窗口计算的准确性？**  
  使用事件时间 + Watermark，允许一定延迟；对于极晚数据，使用侧输出流单独处理。
- **如何在高并发场景下保证滑动窗口计数器的线程安全？**  
  使用细粒度锁（如对每个用户队列加锁）或无锁数据结构（如 `ConcurrentHashMap` + `AtomicLong`）。
