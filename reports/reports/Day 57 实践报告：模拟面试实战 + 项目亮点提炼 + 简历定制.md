# Day 57 实践报告：模拟面试实战 + 项目亮点提炼 + 简历定制

## 1. 练习目标
- 通过模拟面试实战，检验面试题库掌握程度，提升临场应答能力。
- 提炼项目中的3-5个核心亮点（技术难点、业务价值、量化成果），形成“电梯演讲”。
- 针对不同岗位（风控数据开发、金融数据工程师、风险模型开发）定制简历中的项目描述，提高匹配度。

## 2. 实验环境
- 模拟面试形式：自问自答 + 录音 + 计时
- 辅助工具：手机录音、文本编辑器
- 参考文档：`docs/interview_qa.md`、项目代码、`project_highlights.md`

## 3. 核心任务执行

### 3.1 模拟面试实战
- **形式**：独自模拟，手机录音，限时2分钟/题。
- **流程**：
  - 自我介绍（2分钟）
  - 项目介绍（5分钟）
  - 随机抽取10道面试题（覆盖SQL、数仓、ETL、风控、项目深挖）
- **录音回放自评**：
  - 优点：项目介绍逻辑清晰，能引用具体表名和脚本；对幂等性、PSI、KS 等概念回答准确。
  - 不足：
    - “连续登录” SQL 手写卡顿，需要加强。
    - 回答“DuckDB 缺点”时遗漏了迁移方案。
    - 语速偏快，部分地方未分点。

**改进措施**：
- 重写连续登录 SQL 并手写三遍。
- 补充 DuckDB 迁移到 Spark 的方案简述。
- 放慢语速，回答时先说出“第一点、第二点”。

## 6. 思考题
- **如何向非技术面试官介绍项目？**  
  用业务价值开头：“这个项目帮助风控团队每天自动检测数据异常，节省了 1 小时人工核对时间，并能快速定位通过率下降的原因。”
- **最自豪的成就？**  
  监控告警体系：从被动发现到主动告警，异常发现时效提升 90% 以上，直接提升了数据质量保障效率。
- **简历中如何避免堆砌技术名词？**  
  用结果导向描述，例如：“通过设计增量刷新策略，ETL 耗时降低 70%”，而非仅写“使用增量刷新”。
