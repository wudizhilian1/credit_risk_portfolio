# Day 44 实践报告：幂等策略——分区覆盖 / merge key

## 1. 练习目标

- 理解幂等性在数据工程中的重要性：无论执行多少次，结果始终一致。
- 掌握实现幂等性的常用模式：**分区覆盖**（先删除后插入）和 **Merge/Upsert**（基于主键更新或插入）。
- 针对不同数据层（ODS、DWD、DWS、ADS）设计合适的幂等策略。
- 编写幂等性设计文档 `docs/idempotency.md`，并更新相关 ETL 脚本。

## 2. 实验环境

- DuckDB 版本：0.10.0

- 已有 ETL 脚本：`run_full_etl.py`、`etl_load_ods.py` 及各层 SQL 刷新脚本

## 3. 核心任务执行

### 3.1 设计幂等性策略

根据各层数据特点，确定如下策略：

| 数据层  | 幂等策略 | 实现方式           | 说明                                            |
| :------ | :------- | :----------------- | :---------------------------------------------- |
| **ODS** | 分区覆盖 | 先删后插           | 按加载日 `dt` 删除旧分区，再插入新数据          |
| **DWD** | 全量刷新 | 清空全表后重新插入 | 基于整个 ODS 去重，保证每个 `apply_id` 最新状态 |
| **DWS** | 分区覆盖 | 按日期范围先删后插 | 只重算指定 `dt` 区间的汇总                      |
| **ADS** | 分区覆盖 | 同 DWS             | 按统计日期删除后插入                            |

### 3.2 检查现有脚本幂等性

- **ODS 层**：`etl_load_ods.py` 已实现 `DELETE WHERE dt = ...` + `INSERT`，幂等。
- **DWD 层**：`ods_to_dwd_apply.sql` 和 `ods_to_dwd_decision.sql` 使用 `DELETE FROM dwd_apply_latest`（全表清空）后全量插入，幂等。
- **DWS 层**：`dws_channel_daily.sql` 等原本全表清空，改为按日期范围删除后插入，已实现增量幂等。
- **ADS 层**：`refresh_ads.sql` 已按日期范围删除后插入，幂等。

### 3.3 测试幂等性

执行两次相同日期范围的 ETL：

```bash
python scripts/run_full_etl.py --dt_start 2024-01-15 --dt_end 2024-01-15
python scripts/run_full_etl.py --dt_start 2024-01-15 --dt_end 2024-01-15
```

- 第一次：正常处理，表中有数据。
- 第二次：先删除再插入，数据量不变，审计表记录两次运行。
- 验证：`SELECT COUNT(*) FROM dws_channel_daily WHERE dt='2024-01-15'` 两次结果相同。

## 4. 遇到的问题与解决方案

| 问题                             | 原因         | 解决方案                                             |
| :------------------------------- | :----------- | :--------------------------------------------------- |
| DWD 层全量刷新在数据量大时性能差 | 全表扫描     | 数据量小（<15万行），暂可接受；未来可改为增量 upsert |
| 分区覆盖需要知道分区键           | 设计时已明确 | 所有表均以 `dt` 或 `stat_date` 为分区键，保证可覆盖  |
| 幂等性要求原子操作               | 未使用事务   | 所有关键操作已用 `BEGIN TRANSACTION` / `COMMIT` 包裹 |

## 6. 思考题

- 为什么 ODS 层使用分区覆盖而不是 upsert？
  → ODS 数据按加载日分区，通常不会修改历史，分区覆盖可保证重跑时不重复。
- 如果 DWD 表数据量巨大，全量刷新不可行，如何设计增量 upsert？
  → 记录每次 ODS 中 `update_time` 的变化，只处理变化的分区，并使用主键合并（先删后插或 `MERGE`）。
- 幂等性与事务的关系？如何保证原子性？
  → 使用事务包裹删除和插入，确保要么全成功要么全失败，避免中间状态。
