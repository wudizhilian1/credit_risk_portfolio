# Day 22 实践笔记：ETL 1：raw → ODS 加载（按 dt 分区）

## 📌 今日学习目标

- 掌握将原始数据（Parquet 分区）加载到 ODS 物理表的方法。
- 实现按 dt 分区的增量/全量加载，并记录输入输出行数。
- 理解幂等性：重复执行同一加载任务不应导致数据重复。
- 编写可重用的 ETL 脚本，为后续自动化调度做准备。

## 🛠️ 核心任务回顾

### 1. ETL 策略设计

- **增量加载**：每次只处理指定的一天（`dt`），通过参数传入。
- **幂等实现**：先删除目标表中该 `dt` 的所有记录，再插入新数据（`DELETE FROM ... WHERE dt = ...` 后 `INSERT`）。
- **记录审计**：记录输入行数（从视图读取的行数）、输出行数（插入后的行数）及执行时间。

### 2. 编写 ETL 脚本 `scripts/etl_load_ods.py`

### 3. 测试与验证

- **单日加载测试**：

```bash
python scripts/etl_load_ods.py --dt 2024-01-01
```

- **幂等性验证**：再次执行同一命令，输出行数不变，审计表新增两条记录。

### 4. 审计表查询

```sql
SELECT * FROM ods_load_audit ORDER BY load_time DESC LIMIT 10;
```

## 核心概念总结

- **ODS 层**：操作数据存储，保留原始数据最细粒度，是数仓的源头。
- **幂等性**：无论执行多少次，结果一致。通过先删后插实现。
- **增量加载**：按日期分区处理，避免全量扫描。
- **审计日志**：记录每次加载的元数据，便于监控和问题排查。

## ⚡ 性能优化要点

- 删除和插入均在事务内完成，保证原子性。
- 插入时直接使用视图，但视图背后只扫描单日分区，I/O 高效。
- 审计表独立，不影响主表性能。
