# 迟到数据处理策略

## 1. 定义
- **事件日（event_date）**：业务实际发生日期，取自 `apply_time` 或 `decision_time`。
- **加载日（load_date）**：数据被写入数据仓库的日期，即分区字段 `dt`。

## 2. 识别
当 `dt > CAST(apply_time AS DATE)` 时，该记录被视为迟到数据。

## 3. 处理原则
- **DWD 层**：按事件日重新分区，确保业务口径正确。
- **DWS 层**：若已按事件日聚合，需在每日调度中**重算受影响日期**（即迟到数据所属的事件日）。
- **报表层**：对外报表应基于事件日口径，避免因数据迟到导致指标波动。

## 4. 回补流程
- 每日 ETL 从 ODS 读取新增数据（增量），按事件日插入 DWD 事件表。
- 识别哪些事件日有新数据到达，触发这些日期的 DWS 重算。
- 重算 DWS 时采用 **覆盖写入**（先删后插），保证幂等。
