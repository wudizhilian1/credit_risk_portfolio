# 数据血缘工具学习笔记

## 一、数据血缘工具核心认知

### 1. 核心定义

数据血缘（Data Lineage）描述了数据从产生、加工、流转到消费的全生命周期路径，记录了数据在各环节的来源、转换规则、去向。数据血缘工具则是自动化解析、管理、可视化这些血缘关系的专用工具，是企业级数仓治理的核心组件。

### 2. 主流工具（Amundsen、DataHub）核心功能

| 功能模块     | 核心能力                                                     | Amundsen 支持度                                 | DataHub 支持度                              |
| :----------- | :----------------------------------------------------------- | :---------------------------------------------- | :------------------------------------------ |
| SQL 依赖解析 | 自动解析 SQL 脚本中的表 / 字段级依赖关系（如 `SELECT * FROM A JOIN B` 识别 A、B 为来源表） | ✅ 支持主流 SQL 方言（MySQL/PostgreSQL/Hive 等） | ✅ 更全面的解析能力，支持存储过程 / 复杂 SQL |
| 血缘可视化   | 以图形化方式展示表 / 字段的上下游关系，支持钻取、筛选        | ✅ 拓扑图展示，支持表级血缘                      | ✅ 支持表 / 字段级血缘，交互更丰富           |
| 元数据管理   | 关联数据资产的元信息（表结构、负责人、描述）                 | ✅ 轻量级元数据管理                              | ✅ 一站式元数据平台，血缘与元数据深度融合    |
| 数据影响分析 | 当上游表结构变更时，自动识别下游受影响的表 / 任务            | ✅ 基础支持                                      | ✅ 完善的影响分析功能                        |
| 多数据源适配 | 支持数仓主流组件（Hive、Spark、Flink、数仓工具）             | ✅ 主流数据源适配                                | ✅ 适配更多小众数据源，生态更全              |

### 3. 企业级价值

- 解决数仓「黑盒」问题：清晰追溯数据来源，定位数据质量问题根因；
- 降低变更风险：修改表结构 / ETL 脚本前，预判下游影响范围；
- 合规审计：满足金融、政务等行业的数据溯源合规要求；
- 资产盘点：清晰梳理数仓内表的依赖关系，优化数仓架构。

## 二、轻量化实践：Python 脚本解析 SQL 生成血缘关系

### 1. 实现思路

核心逻辑：解析 SQL 脚本中的 `FROM`/`JOIN`（来源表）、`INSERT INTO`/`CREATE TABLE AS`（目标表），提取表名并建立「来源表 → 目标表」的血缘关系，最终生成 Markdown 格式的血缘文档。

### 2. 完整代码实现

```python
import re
from typing import Dict, List, Set

class SQLBloodlineParser:
    """SQL 血缘关系解析器，提取表名并生成血缘关系"""
    
    def __init__(self):
        # 正则表达式：匹配 FROM/JOIN 后的表名（支持别名、多表连接）
        self.source_table_pattern = re.compile(
            r'(?:FROM|JOIN)\s+([a-zA-Z0-9_]+)(?:\s+AS\s+[a-zA-Z0-9_]+)?', 
            re.IGNORECASE
        )
        # 正则表达式：匹配 INSERT INTO/CREATE TABLE AS 后的目标表名
        self.target_table_pattern = re.compile(
            r'(?:INSERT\s+INTO|CREATE\s+TABLE)\s+([a-zA-Z0-9_]+)', 
            re.IGNORECASE
        )

    def parse_sql_file(self, sql_file_path: str) -> Dict[str, Set[str]]:
        """
        解析 SQL 文件，返回血缘关系字典
        :param sql_file_path: SQL 文件路径
        :return: 血缘关系 {目标表: {来源表1, 来源表2,...}}
        """
        bloodline = {}
        try:
            with open(sql_file_path, 'r', encoding='utf-8') as f:
                sql_content = f.read().replace('\n', ' ').strip()
                
                # 提取目标表（支持多个目标表，如批量建表场景）
                target_tables = self.target_table_pattern.findall(sql_content)
                # 提取来源表（去重）
                source_tables = set(self.source_table_pattern.findall(sql_content))
                
                # 构建血缘关系
                for target in target_tables:
                    if target not in bloodline:
                        bloodline[target] = set()
                    bloodline[target].update(source_tables)
        except FileNotFoundError:
            print(f"错误：未找到 SQL 文件 {sql_file_path}")
        except Exception as e:
            print(f"解析失败：{str(e)}")
        return bloodline

    def generate_md_doc(self, bloodline: Dict[str, Set[str]], md_file_path: str):
        """
        生成 Markdown 格式的血缘文档
        :param bloodline: 解析后的血缘关系
        :param md_file_path: 输出的 MD 文件路径
        """
        md_content = "# 数据血缘关系文档\n\n"
        md_content += "## 生成说明\n"
        md_content += "- 解析方式：基于 SQL 脚本中的 FROM/JOIN/INSERT INTO 关键字提取\n"
        md_content += "- 血缘粒度：表级（字段级需更复杂的解析逻辑）\n\n"
        md_content += "## 血缘关系列表\n"
        md_content += "| 目标表 | 来源表 |\n"
        md_content += "|--------|--------|\n"
        
        # 填充血缘关系
        for target, sources in bloodline.items():
            source_str = ", ".join(sources) if sources else "无"
            md_content += f"| {target} | {source_str} |\n"
        
        # 写入 MD 文件
        with open(md_file_path, 'w', encoding='utf-8') as f:
            f.write(md_content)
        print(f"血缘文档已生成：{md_file_path}")

# 示例使用
if __name__ == "__main__":
    # 初始化解析器
    parser = SQLBloodlineParser()
    
    # 解析 SQL 文件（替换为你的 SQL 文件路径）
    sql_path = "example.sql"
    bloodline_result = parser.parse_sql_file(sql_path)
    
    # 生成 MD 文档（替换为你的输出路径）
    md_path = "data_bloodline.md"
    parser.generate_md_doc(bloodline_result, md_path)
```

### 3. 使用说明

#### 前置条件

- 安装 Python 3.7+（无需额外依赖，仅使用内置库）；

- 准备待解析的 SQL 文件（示例 

  ```
  example.sql
  ```

  ），内容参考：

  ```sql
  -- example.sql 示例内容
  CREATE TABLE dw_user_order 
  AS 
  SELECT u.id, u.name, o.order_id, o.amount 
  FROM ods_user u 
  JOIN ods_order o ON u.id = o.user_id;
  
  INSERT INTO dw_user_order_summary
  SELECT user_id, SUM(amount) FROM dw_user_order GROUP BY user_id;
  ```

  

#### 执行步骤

1. 将上述 Python 脚本保存为 `sql_bloodline_parser.py`；

2. 替换脚本中 `sql_path` 和 `md_path` 为实际文件路径；

3. 运行脚本：

   ```bash
   python sql_bloodline_parser.py
   ```

   

#### 输出效果（data_bloodline.md）

```markdown
# 数据血缘关系文档

## 生成说明
- 解析方式：基于 SQL 脚本中的 FROM/JOIN/INSERT INTO 关键字提取
- 血缘粒度：表级（字段级需更复杂的解析逻辑）

## 血缘关系列表
| 目标表 | 来源表 |
|--------|--------|
| dw_user_order | ods_user, ods_order |
| dw_user_order_summary | dw_user_order |
```

### 4. 脚本局限性与优化方向

- 局限性：仅支持简单 SQL、不识别子查询 / 临时表、不支持字段级血缘；
- 优化方向：
  1. 集成专业 SQL 解析库（如 `sqlparse`、`antlr4`），提升复杂 SQL 解析能力；
  2. 支持字段级血缘解析（提取 SELECT 后的字段与来源表字段的映射）；
  3. 适配更多 SQL 方言（如 Hive SQL、Spark SQL 的特有语法）；
  4. 生成可视化的 Mermaid 流程图（替代纯表格）。

## 三、总结

### 1. 核心认知

- 企业级数据血缘工具（Amundsen/DataHub）：自动化、全链路、可视化，适配复杂数仓场景；
- 轻量化方案（Python 脚本）：低成本、易实现，适合小型项目 / 手动维护场景，可满足基础血缘追溯需求。

### 2. 实践建议

- 小型项目 / 个人学习：使用上述 Python 脚本快速生成表级血缘文档；
- 企业级数仓：优先选用 Amundsen/DataHub，结合数仓架构实现自动化血缘管理；
- 进阶方向：基于脚本扩展字段级解析能力，或对接元数据平台实现血缘自动同步。
