# 数据质量规则文档

本文档定义了信贷风控数仓项目中各层数据质量监控的规则，包括检查项、阈值、告警级别和处理建议。所有规则均需通过自动化脚本每日执行，确保数据及时发现问题并推动修复。

---

## 1. ODS 层数据质量规则

ODS 层保留原始数据，监控主要关注源系统数据的完整性、有效性。

| 规则名称   | 检查对象                                     | 规则描述                                              | 阈值/条件                      | 告警级别 | 处理建议                   |
| ---------- | -------------------------------------------- | ----------------------------------------------------- | ------------------------------ | -------- | -------------------------- |
| 主键唯一性 | `ods_apply`                                  | 同一 `apply_id` 不应重复（但 ODS 允许重复，仅做记录） | 重复率 > 0%                    | WARN     | 记录重复样本，通知上游排查 |
| 字段空值率 | `ods_apply.user_id`, `ods_decision.decision` | 关键字段空值比例                                      | > 5%                           | WARN     | 检查数据源是否缺失         |
| 金额范围   | `ods_apply.amount`                           | 金额应在合理区间（如 1000~50000）                     | 超出区间比例 > 1%              | ERROR    | 排查源系统异常值           |
| 迟到数据   | `ods_apply`                                  | 加载日 `dt` 与事件日 `apply_time` 差值                | `dt > apply_time` 的记录数 > 0 | INFO     | 记录迟到数据，触发下游重算 |

---

## 2. DWD 层数据质量规则

DWD 层经过清洗去重，应满足业务唯一性、完整性要求。

| 规则名称     | 检查对象                                                   | 规则描述             | 阈值/条件       | 告警级别 | 处理建议                   |
| ------------ | ---------------------------------------------------------- | -------------------- | --------------- | -------- | -------------------------- |
| 主键唯一性   | `dwd_apply_latest`                                         | `apply_id` 应唯一    | 重复记录数 > 0  | ERROR    | 检查去重逻辑，修复 ETL     |
| 字段空值率   | `dwd_apply_latest.user_id`, `dwd_decision_latest.decision` | 关键字段空值比例     | > 1%            | WARN     | 补充缺失数据或调整清洗规则 |
| 决策完整性   | `dwd_apply_latest` 与 `dwd_decision_latest` 关联           | 每个申请应有对应决策 | 决策缺失率 > 1% | WARN     | 检查决策表是否漏同步       |
| 策略版本缺失 | `dwd_decision_latest.strategy_version`                     | 策略版本不应为空     | 空值比例 > 0%   | WARN     | 检查决策表是否包含版本信息 |

## 3. DWS 层数据质量规则

DWS 层为汇总表，需监控数据量的稳定性、字段值的合理性及分布漂移。

### 3.1 行数波动监控
每日记录 DWS 表行数，与前一日对比，波动超过阈值则告警。

| 表名                    | 波动阈值                             | 告警级别     |
| ----------------------- | ------------------------------------ | ------------ |
| `dws_channel_daily`     | 日环比 > 20% 为 ERROR，> 10% 为 WARN | ERROR / WARN |
| `dws_strategy_daily`    | 日环比 > 20% 为 ERROR，> 10% 为 WARN | ERROR / WARN |
| `dws_reject_topn_daily` | 日环比 > 20% 为 ERROR，> 10% 为 WARN | ERROR / WARN |

### 3.2 关键字段空值监控
关键字段不应为空或空字符串。

| 表名                    | 字段            | 阈值        | 告警级别 |
| ----------------------- | --------------- | ----------- | -------- |
| `dws_strategy_daily`    | `strategy_name` | 空值率 > 0% | WARN     |
| `dws_channel_daily`     | `channel_name`  | 空值率 > 0% | WARN     |
| `dws_reject_topn_daily` | `reason_desc`   | 空值率 > 0% | WARN     |

### 3.3 负值检测
数值字段不应出现负值（如申请量、拒绝次数等）。

| 表名                    | 字段                                  | 阈值         | 告警级别 |
| ----------------------- | ------------------------------------- | ------------ | -------- |
| `dws_channel_daily`     | `apply_cnt`, `pass_cnt`, `reject_cnt` | 出现任何负值 | ERROR    |
| `dws_strategy_daily`    | `apply_cnt`, `pass_cnt`, `reject_cnt` | 出现任何负值 | ERROR    |
| `dws_reject_topn_daily` | `reject_cnt`                          | 出现任何负值 | ERROR    |

### 3.4 分布稳定性监控（PSI）
监控拒绝原因分布的稳定性，以 7 天前为基准。

| 表名                             | PSI 阈值                                                     | 告警级别        |
| -------------------------------- | ------------------------------------------------------------ | --------------- |
| `dwd_decision_latest` (拒绝原因) | PSI < 0.1: 稳定；0.1 ≤ PSI < 0.25: 轻微波动；PSI ≥ 0.25: 显著漂移 | 显著漂移 → WARN |
| （未来可扩展至其他特征）         |                                                              |                 |

## 4. ADS 层数据质量规则

ADS 层面向最终应用，需确保与上游数据一致，并支持追溯。

### 4.1 ADS vs DWS 一致性对账
每日检查 ADS 核心指标是否与 DWS 汇总一致。

| 表名                  | 对比对象                     | 规则                                                | 差异容忍度                          | 告警级别          |
| --------------------- | ---------------------------- | --------------------------------------------------- | ----------------------------------- | ----------------- |
| `ads_overview_daily`  | `dws_channel_daily` 按日汇总 | `apply_cnt`, `pass_cnt`, `reject_cnt` 应相等        | 差异绝对值 ≤ 5 为 OK，> 20 为 ERROR | OK / WARN / ERROR |
| `ads_channel_quality` | `dws_channel_daily` 按月汇总 | `apply_cnt`, `pass_rate` 应近似（允许四舍五入误差） | 误差 < 0.01% 为 OK，否则 WARN       | OK / WARN         |

### 4.2 钻取表完整性
`ads_reject_drilldown` 中抽取的样本应与 DWD 明细一致，且数量符合预期。

| 表名                   | 规则                                              | 告警级别    |
| ---------------------- | ------------------------------------------------- | ----------- |
| `ads_reject_drilldown` | 每个拒绝原因每天至少应有 1 条样本（若当日有拒绝） | 缺失 → WARN |

## 5. 单元测试与回归测试

除了每日监控，还需通过单元测试保证 ETL 逻辑正确性。

### 5.1 单元测试覆盖（pytest）
| 测试点                | 描述                                                         | 执行频率       |
| --------------------- | ------------------------------------------------------------ | -------------- |
| DWS 与 DWD 指标一致性 | 随机抽取某日某渠道，验证申请量、通过量等                     | 每次代码变更后 |
| ADS 与 DWS 汇总一致性 | 随机抽取某日，验证 `ads_overview_daily` 与 DWS 汇总一致      | 每次代码变更后 |
| 拒绝原因 TopN 总数    | 验证 `dws_reject_topn_daily` 中每日拒绝总数与 DWD 拒绝记录数一致 | 每次代码变更后 |

### 5.2 回归测试
在 ETL 脚本修改后，需重新运行全量对账，确保历史数据未受影响。

## 6. 告警规则配置与自动化

### 6.1 告警规则表
为了动态管理阈值，设计了配置表 `dq_alert_rules`，包含规则名称、监控对象、指标类型、警告阈值、错误阈值、是否激活等字段。示例规则如下：

| rule_name             | table_name         | metric               | field_name    | threshold_warn | threshold_error |
| --------------------- | ------------------ | -------------------- | ------------- | -------------- | --------------- |
| 行数波动-日环比       | dws_channel_daily  | row_count_pct_change | NULL          | 10.0           | 20.0            |
| 空值率-策略名称       | dws_strategy_daily | null_rate            | strategy_name | 0.0            | 0.0             |
| 负值检测-申请量       | dws_channel_daily  | negative_amount_cnt  | NULL          | 0              | 0               |
| ADS vs DWS 申请量差异 | ads_overview_daily | apply_diff           | NULL          | 5              | 20              |

### 6.2 告警历史表
所有触发的告警记录存入 `dq_alert_history`，包含告警时间、级别、规则、消息、是否解决等字段，便于追溯和复盘。

### 6.3 告警引擎
每日 ETL 完成后，运行 Python 脚本 `alert_engine.py`：
- 读取激活的规则，从监控表获取最新值。
- 与阈值比较，产生 WARN 或 ERROR 级别告警。
- 将告警写入历史表，并通过控制台输出（可扩展邮件、钉钉等）。

---

## 7. 规则执行与告警

- **执行频率**：每日一次，在 DWS/ADS 层数据刷新后执行。
- **结果存储**：监控结果写入 `dq_dws_monitor`、`reconcile_ads_log` 等表，告警历史写入 `dq_alert_history`。
- **告警方式**：如产生 `WARN` 或 `ERROR` 级别告警，通过控制台输出（可扩展邮件、钉钉）。
- **处理流程**：收到告警后，需在当日排查问题，修复数据或调整规则，并在 `dq_alert_history` 中标记 `is_resolved = true`。
